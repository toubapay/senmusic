# ProMusic mobile (Flutter)

Listener app: search, HLS playback, subscriptions, offline downloads.
Android + iOS only (the `linux`/`macos`/`windows`/`web` targets `flutter
create` scaffolds by default were removed — `web/player` is already the
web client).

## Run

```bash
cd mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=http://localhost:8080
```

No login/signup route exists yet (see root `CLAUDE.md`) — open the Session
tab and paste a JWT (e.g. one generated by `services/api/public/test-console.html`),
same `token` storage convention as `web/player`'s and `web/dashboard`'s
Settings pages, just backed by Keychain/Keystore here
(`flutter_secure_storage`) instead of `localStorage`.

## What's here vs. what it replaced

This used to be a handful of loose React Native pieces
(`src/api/client.js`, `usePlayTracking.js`, `PlayerScreen.jsx`,
`offlineManager.js`) with no app shell — same state `web/player` and
`web/dashboard` were in before those got built out. Ported to Flutter/Dart
1:1 in behavior:

| Dart | React Native original | Behavior preserved |
|---|---|---|
| `lib/api/client.dart` | `src/api/client.js` | same endpoints, adds search/tracks/subscriptions to match web/player's scope |
| `lib/services/play_tracking.dart` | `src/hooks/usePlayTracking.js` | same 10s heartbeat, 30s "counted" threshold, flush-on-pause/end/dispose |
| `lib/screens/player_screen.dart` | `src/screens/PlayerScreen.jsx` | `just_audio` (ExoPlayer/AVPlayer, same engines `react-native-video` used) replaces the RN video component; same paywall-on-403 behavior |
| `lib/services/offline_manager.dart` | `src/offline/offlineManager.js` | same AES-256-CTR-encrypted-file contract, same license lifecycle (`refreshLicenses`/`purgeAllKeys`) |

## Verified, and what wasn't

`flutter analyze` (0 issues) and `flutter test` (the app actually boots to
the home tab with providers wired up) both pass. There's no Android SDK or
iOS toolchain in the sandbox this was built in, so an actual device/emulator
run and a release build were **not** verified — do that before shipping.

## Known gaps, same pattern as the rest of this repo

Search, streaming, and checkout will correctly reach the API and fail
there until Meilisearch, a live GCS+CDN backend, and PayDunya keys exist —
see the root `DEPLOY.md`.

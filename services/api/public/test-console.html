ProMusic API Test Console

Talks to whichever origin serves this file (same-origin, no CORS setup needed). Covers every route in routes/*.js. No login route exists yet, so use the token generator below with any UUID as the user id — for routes that need real rows (a track, an artist, a plan), insert them via psql against your local Postgres first.

Test token generator

Signs a real HS256 JWT client-side with Web Crypto, matching what lib/auth.js verifies ({ sub, exp } → req.user.id). Paste the same JWT_SECRET your API process is running with.

Search — GET /v1/search

Unauthenticated. Needs Meilisearch reachable + indexed data.

—

Search — GET /v1/search/genre/:genre

Unauthenticated. Most-played tracks in a genre.

—

Tracks — GET /v1/tracks/:trackId

Auth required. Metadata (title, artists, album, access) for the player screen.

—

Streaming — GET /v1/tracks/:trackId/stream/master.m3u8

Auth required. Needs a ready track in Postgres and its HLS files in GCS. 256k variant is stripped server-side for non-premium users. Extracted variant URLs below already carry a signed short-lived stream token (?st=) — open one directly to exercise the unauthenticated variant-playlist route. 

—

Plays — POST /v1/plays

Auth required. Opens a play session.

—

Plays — PATCH /v1/plays/:playId

Auth required. Heartbeat; flips counted at ≥30 000 ms.

—

Subscriptions — POST /v1/subscriptions/checkout

Auth required. Needs a row in plans with matching code.

—

Subscriptions — GET /v1/subscriptions/me

Auth required.

—

Subscriptions — POST /v1/webhooks/paydunya

Unauthenticated (IPN). Server always re-confirms with the real PayDunya API via lib/paydunya.js, so without live PayDunya credentials this will fail past body-parsing — useful to confirm the route + JSON body wiring, not to simulate a full payment. 

—

Artist uploads — POST /v1/artist/tracks

Auth required + the user must already own a row in artists.

—

Artist uploads — GET /v1/artist/tracks

Auth required. Lists the caller's own tracks.

—

Artist uploads — GET /v1/artist/tracks/:id

Auth required. Polls one track's pipeline status.

—

Offline — POST /v1/offline/downloads

Auth required + active subscription + track must be ready.

—

Offline — GET /v1/offline/licenses

Auth required. The renewal heartbeat; 403 means "purge keys".

—

Offline — DELETE /v1/offline/downloads/:trackId

Auth required.
